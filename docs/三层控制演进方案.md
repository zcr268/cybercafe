# CyberCafe 三层控制演进方案（终版冻稿）

> 状态：已冻结 · 决策全部收敛 · 待实现
> 日期：2026-10-12
> 前置阅读：[现有架构交互图](cybercafe-architecture.html)

## 一 · 目标与形态

把现「云管端 ↔ 设备」两级模型演进为三层控制结构：

```
L1 云控制（多网吧全局）
   │ 聚合上报 / 策略下发 / 批次签发 / 分发
L2 网吧控制（本期单点，后话对等集群）
   │ 统一 API / 任务调度 / 转发 / 缓存 / 预留机
L3 工作机（无公网暴露）
     四组件推理：OCR / 文生图 / 文生视频 / H3
```

关键原则：

1. **L3 永不做公网暴露**——全部经 L2 转发/中转，上报任意 L2 节点。
2. **客户端只见 L2 统一 API**——引擎差异由 L2 适配层吞掉（统一 API · 多适配器），换引擎/混部不影响对外契约。
3. **负载路由在「模型已部署的机器池」内发生**——池内按在途任务数最少分配，池满才排队。
4. **本期专注任务型非流式请求**：OCR / 文生图 / 文生视频 / H3；不做文生文 LLM、不做 SSE 流式。
5. **不做跨网吧调度**——排队仅限本网吧；不做配额/强制保留阈值（删），仅保留「预留机保护」。

## 二 · 三层职责

| | L1 云控制 | L2 网吧控制（本期单点） | L3 工作机 |
|---|---|---|---|
| 控制面 | 全局大盘 · 预留机配置 · 最高分发节点 · 批次码签发 · L2 身份注册 | 设备/任务管理 · 模型池索引 · 任务调度 · 镜像与权重缓存 | 心跳上报 · 任务执行 · 部署流水线 |
| 数据面 | 机房聚合统计 · 预留策略下发 | 统一 API 入口 · 任务队列 · 转发 · 结果存储 | 四组件推理（无公网暴露） |
| 存储 | 全局配置 · 完整批次码 · 机房汇总 | 本机房批次码 · 设备清单 · 任务/队列状态 | 本地配置 + 模型权重 |
| 鉴权 | L2 注册身份 · 批次码签发 | 网吧 API Key · 限流 · L3 身份校验 | 向 L2 标识自身（设备密钥仅识别） |
| 容灾 | L2 离线期间聚合降级 | 单点（本期）→ 对等集群（后话） | 跟随 L2，本期不做公网降级 |

### 识别语义（已收敛）

- **批次码**：L1 保留完整、L2 保留本机房；仅用于识别机器来源，不做配额。
- **设备密钥**：仅 L3 向 L2 标识自身身份，不做外部鉴权（网吧内机器本身私有）。
- **配额 / 强制保留阈值机制**：逻辑删除，不实现。

## 三 · 推理面 API 契约

| 能力 | L3 后端事实接口 | L2 统一包装（客户端视角） |
|---|---|---|
| OCR | PaddleOCR / RapidOCR（文字 + bbox + 置信度） | 提交图像 → 结构化文本结果 |
| 文生图 | OpenAI Images 兼容（`/v1/images/generations`） | 提交 prompt → 图片 b64 |
| 文生视频 | ComfyUI（`/prompt` 提交 + `/history` 查结果） | 提交 → task_id → 轮询 → 视频 |
| H3 生成 | sd-server（`/sdcpp/v1/vid_gen`，OpenAI 兼容形态，端口 11435） | 提交 → task_id → 轮询 → webm |

**统一 API · 多适配器（关键约束）**

- 客户端永远只面对 L2 统一任务 API（如 `POST /v1/tasks`），请求参数为后端无关语义字段（prompt / 尺寸 / 时长 / 档位等），不使用引擎专用端点。
- L2 按机器实际部署选择适配器：ComfyUI → `/prompt`；H3 → `/sdcpp/v1/vid_gen`；PaddleOCR → RapidOCR 接口；文生图 → Images 兼容。
- 结果：同一个客户端请求，L2 路由到不同后端机器时自动用对应 API；机器换引擎、集群混部，客户端无感知。每类能力一个统一契约，未来引擎实现同一适配器接口即可插入。

## 四 · 任务生命周期（统一非流式）

```
提交  POST /v1/tasks  {component, model, params} → {task_id}
路由  L2 查模型池索引（仅该模型已部署的机器）→ 池内按在途任务数最少选 L3
排队  池内全忙 → 入 L2 共享队列（预留机不参与可切换）
执行  L3 执行推理，进度节点上报（沿用现有机制 API 化）
回传  结果上报 L2 存储，客户端 GET /v1/tasks/{id} 轮询取回
终态  success / failed / canceled，结果保留窗口供轮询
```

## 五 · 关键机制

### ① 模型池路由与负载

- 池 = 「已部署该模型档位」的机器集合。
- 负载均衡仅在池内按「在途任务数最少」分配；池满才排队。
- 优先路由「已加载该模型」的机器；其次「可加载」的空闲机（配合动态切模型）。

### ② L2 集群演进位（本期单点）

- 本期：单 L2 节点，持有任务队列、设备清单、镜像/权重缓存，对外一个统一入口。
- 预留演进位（后话对等集群）：
  - L3 上报目标地址可配置切换（L3 上报任意一台，互相同步，任意节点故障自动切换上报）；
  - 任务 / 设备状态入共享存储接口；
  - 后话只换存储与调度内核，对外协议不动。

### ③ 镜像预生成缓存（两层，均无组件白名单）

- **镜像层（部署产物）**：
  - 规格指纹 = `GPU 型号 + 显存 + 驱动版本 + 内存 + CPU 组`（沿现有硬件指纹算法扩展，同 GPU 不同驱动不可共用）；
  - 镜像 tag = `规格指纹 + 组件版本`；
  - L2 本地镜像仓库，同规格机器命中即拉取免构建；首次遇新规格/新版本由一台生成并推送入仓。
- **权重层（模型产物）**：
  - 以 `(组件, 模型标识, 版本)` 为键的通用仓库；
  - 任何组件权重命中即免下载：PaddleOCR 模型、ComfyUI 工作流模型、MiniMax H3 权重包（最小档 ≈27GB：denoiser 8.06GB + 文本编码器 13.1GB + 视频/音频 VAE）及后续所有组件，一律纳入，不做白名单。

### ④ 动态切模型 + 预留机保护

- 触发：某模型有排队任务，且存在「未运行该模型」或「可卸载的空闲模型」的机器。
- 空闲判定：分钟级无在途任务。
- 流程：卸载 → 拉取/加载（缓存命中则快）→ 就绪上报 → 再分配；切换后设冷却期防抖动。
- **预留机保护（L1 下发）**：L1 按**模型档位设最少台数**下发预留配置；L2 切模型永不触碰预留机，保护已知流量高峰不被排队挤占。

### ⑤ 网吧统一 API 与安全

- 单一入口（暂定 CF 自动隧道）+ 网吧 API Key 鉴权 + 限流。
- 任务型端点统一「提交 → task_id → 轮询」；L2 只做统一网关与转发，不自定义协议。

## 六 · 本期不做（边界冻结）

- 文生文 LLM / SSE 流式链路（本期全部任务非流式）
- 跨网吧调度与队列溢出（只本网吧排队）
- 配额 / 强制保留阈值机制
- L2 对等集群实现（本期单点，留演进位）
- L3 公网暴露 / 降级直连 / 结果回调（后话）
- L1 机房分配比例
- L2 集群化（后话）

## 七 · 已冻结决策（全部落地）

1. 四组件：OCR = PaddleOCR；文生图 = OpenAI Images 兼容；文生视频 = ComfyUI；H3 = sd-server（OpenAI 兼容形态）。
2. 统一 API + 多适配器：客户端不感知后端。
3. 预留机 = 按模型档位设最少台数；结果回传先轮询。
4. L2 本期单点、对等集群后话。
5. 缓存两层全组件通用（无白名单），权重缓存包含 H3。
6. 不做：比例分配、跨网吧、文生文、流式、配额、L3 公网。
