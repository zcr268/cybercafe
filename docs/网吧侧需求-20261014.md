## 一 · 范围与现状基线

**范围**：网吧侧全部能力（L1 云控制 / L2 网吧控制 / L3 工作机）。**不含** KeyCompute——二者是**两个独立实体**，各自独立部署与升级（L2 与 slave 同机或异机不作为约束），仅通过第四节的接口对接。

| 层级 | 设计目标 | 代码现状 | 缺什么 |
|---|---|---|---|
| L1 云控制 | 全局大盘 · 预留机配置 · 最高分发节点 · 批次码签发 · L2 身份注册 | 批次码签发与装机入网已建；脚本分发已建 | L2 身份注册、预留机策略、镜像/权重分发仓、多机房聚合大盘（现仅设备平铺） |
| L2 网吧控制 | 统一 API · 任务队列 · 调度 · 适配 · 缓存 · 本机房状态 | **整层无代码**（无进程、无目录） | 全部 |
| L3 工作机 | 四组件推理 · 心跳 · 部署流水线 · 无公网暴露 | 注册/心跳/进度/部署流水线已建；OCR 已建，文生视频能力已由 H3 承载 | 文生图组件；且现状每台机器自建公网隧道直出，**违反「L3 永不公网暴露」红线** |

> **名称口径**：「**文生视频**」是能力口径（对外契约名），**H3** 只是当前承载该能力的模型（`sd-server`，`/sdcpp/v1/vid_gen`，端口 11435）。模型可替换——ComfyUI 等其它实现未来经同一适配器接入，本期不做。

## 二 · 阶段划分

- **阶段一 · 网吧侧自建（先做）**：L2 落地与三层闭环（R1–R13）。此阶段 L2 对外形态按 R2/R3 定型，不等待外部接入方。
- **阶段二 · KeyCompute 接入（后做）**：按 I1–I4 对接 slave，打通「KC 收单 → L2 干活 → 用量回执 → KC 计费」。

---

## 三 · 需求条目

优先级定义：**P0** = 三层不成立则无法闭环；**P1** = 效率与可用性；**P2** = 后话演进位。

| 编号 | 需求 | 验收标准（可验证） | 依赖 | 优先级 |
|---|---|---|---|---|
| **R1** | L2 服务骨架与本地状态库 | 独立进程可起停；持久化设备/任务/队列/批次；L1 离线时仍能接单与执行 | — | P0 |
| **R2** | L2 统一任务 API | `POST /v1/tasks` 返回 `task_id`；`GET /v1/tasks/{id}` 轮询取回；终态 `success/failed/canceled`；结果保留窗口可配 | R1 | P0 |
| **R3** | L2 入口网关与鉴权 | 网吧 API Key 校验；超限返回 429；无 Key 请求被拒；L3 上报身份校验 | R1 | P0 |
| **R4** | 任务队列与模型池调度 | 池 = 已部署该档位的机器集合；池内按「在途任务数最少」分配；池满入队；队列长度与在途数可查询 | R1,R2 | P0 |
| **R5** | 组件适配层（统一契约 · 多适配器） | 客户端只用后端无关字段（prompt/尺寸/时长/档位）；OCR、文生图、文生视频各一适配器；换模型或混部不改客户端 | R1,R2 | P0 |
| **R6** | L3 收口：撤销公网直出 | L3 不再自建公网隧道；外部无法直达 L3 端口；调用与结果全部经 L2 转发 | R2,R3 | P0 |
| **R7** | 缓存两层（全组件通用） | 镜像按「规格指纹 + 组件版本」命中即免构建；权重按「组件 + 模型 + 版本」命中即免下载；跨机命中可验证（第二次部署耗时显著下降） | R1 | P1 |
| **R8** | L1→L2 下发通道 | 四类下发闭环：L2 身份签发、预留机配置、批次码、脚本/镜像/权重分发；下发可审计 | R1 | P1 |
| **R9** | L2→L1 聚合上报 | 机房级汇总（设备/任务/队列/缓存命中）定时上行；L1 可查 | R1 | P1 |
| **R10** | L1 全局大盘 | 按网吧/机房维度聚合展示；含设备与任务统计；不再是全局平铺列表 | R9 | P1 |
| **R11** | 文生图组件落地 | 部署 + OpenAI Images 兼容 `/v1/images/generations`；经 L2 统一 API 可提交与取回 | R5 | P1 |
| **R12** | 动态切模型 + 预留机保护 | 有排队且存在空闲可切机器时自动切换；切换后设冷却期；预留机永不被切换触碰 | R4,R7 | P2 |
| **R13** | L2 对等集群演进位 | L3 上报地址可配置切换；任务/设备状态走共享存储接口；对外协议不变 | R1 | P2 |

**已完成、不列为需求**（作为基线保持）：批次码签发与装机入网、设备注册/心跳/进度上报、L1→L3 脚本与组件下发、L3 部署流水线、OCR 端到端、文生视频能力（H3 承载）。

## 四 · 与 KeyCompute 的接口需求（阶段二）

KeyCompute 的 slave 接收外部真实请求，网吧侧接住并干完。两系统独立，接口是唯一耦合点：

| 编号 | 接口需求 | 验收标准 | 优先级 |
|---|---|---|---|
| **I1** | L2 转发入口 | 能接收 slave 转发的任务（组件类型 + 后端无关参数），按 R2 立即返回 `task_id`（异步，不阻塞 slave） | P0 |
| **I2** | 结果回传 | 任务终态与结果可由 slave 按 `task_id` 取回；失败原因可读 | P0 |
| **I3** | 身份与授权 | slave 以网吧 API Key 或专用通道被 L2 认可；无凭据请求被拒 | P0 |
| **I4** | 用量回执（必做） | 每个任务吐出关键用量事实（组件 / 模型 / 耗时 / 机台 / 输入输出规模）；**L2 只给事实，费用计算归 KeyCompute** | P0 |

> 接口形态以 R2 的统一任务 API 为基准：对 slave 与对外部客户端是同一套契约，不新增私有协议。

## 五 · 已定口径（2026-10-14 确认）

| # | 议题 | 定论 | 对本文档的影响 |
|---|---|---|---|
| 1 | slave → L2 调用形态 | **L2 先按既定形态建，KC 接入后置** | 拆出第二节阶段划分；I1–I4 归阶段二，不阻塞阶段一 |
| 2 | 计费信息归属 | **L2 吐关键事实，KC 负责算费** | I4 由「若需要」升为必做 P0，并写明分工边界 |
| 3 | slave 与网吧的数量关系 | **暂不考虑** | 不在一对一/一对多上设约束，接口按单网吧 L2 实例设计 |
| 4 | 文生视频命名口径 | **「文生视频」是能力口径，H3 只是一个模型** | 全文改为能力/模型两级表述；适配器按能力定义，模型可替换 |
| 5 | L2 部署形态 | **两系统必是两个独立实体**；同机或异机不重要 | 明确独立部署与升级，部署形态不作为需求约束 |
